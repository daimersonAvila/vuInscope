One scan, five answers

  • Where the errors are

    {{ rule_count }} checks cover hard-coded secrets, SQL and command injection, unsafe deserialisation, weak cryptography, XSS sinks, debug flags and risky cloud or container settings. Every finding points to a file and line.

  • How likely an attack is

    A Markov chain turns your findings into an attack path — from first contact to full compromise — and gives a 0–100 risk score with the most probable route highlighted.

  • How to solve it

    Each finding carries a fix and a corrected example. Ask the AI assistant for a tailored explanation of any finding, written for the exact lines in your code.

  • What to do in the cloud

    Mitigation playbooks with ready-to-review commands for AWS, Linux and Kubernetes. They are simulation only: VulnScope never executes anything.

  • Where it is in its lifecycle

    Register findings in the vulnerability log. A second Markov chain learns from your status changes and forecasts how many steps remain until each one is closed. Exact duplicates are refused with a clear notice.

How a scan works

  1. Upload

    Drop a compressed project. It is unpacked in memory with limits against zip bombs and path tricks; dependency folders like node_modules and .venv are skipped.

  2. Scan

    Rules read each text file line by line. Secrets are masked the moment they are found, so they never appear in results or reach the AI.

  3. Model

    Findings are weighted by severity and fed into the attack-path chain to compute risk and the likeliest route to compromise.

  4. Fix

    Work through the list by severity, ask the AI for help, copy a playbook, or add everything to the registry in one click.

Built to be exposed to the internet

  • Strict Content-Security-Policy with no inline scripts or styles
  • HSTS, frame, referrer, MIME-sniffing and permissions headers on every response
  • Signed, expiring tokens; passwords stored only as salted hashes
  • Rate limits on every endpoint and a lockout after repeated failed logins
  • Upload size, entry-count and decompression limits
  • Parameterised SQL and a unique constraint behind the duplicate guard
  • Generic error messages; details stay in server logs

Your code stays yours

Archives are processed in memory and discarded after the response. When you ask the AI for help, only a few redacted lines around a finding are sent to a public AI service, and only after you click. Do not upload code you are not allowed to share with third parties.
